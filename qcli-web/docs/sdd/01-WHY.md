# Why We Built qcli (Web Version)

## The Problem

qubi's Agentic Flows web designer is a visual drag-and-drop tool. Building workflows requires manually dragging nodes, configuring properties one by one, drawing connections, and clicking Save. Every workflow is built visually, by hand.

This doesn't scale. And it locks out AI-powered development tools that work through code and terminals.

## The Opportunity

UiPath ships a CLI tool that enables CI/CD and developer workflows. qubi needs the same. But we go further — we pair it with an AI Skill so that Claude Code or Kiro can generate entire workflows from plain English.

## What We're Solving

1. **No programmatic access** — there's no way to create/edit workflows without the GUI
2. **No AI integration** — AI agents can't interact with a visual canvas
3. **No automation of workflow creation** — every workflow must be hand-built
4. **No local validation** — you have to save to the server to know if something is wrong

## The Differentiator

Every automation platform requires a human to visually build workflows. Even UiPath's CLI is just for packaging — you still need their Studio to design.

**qubi + qcli + AI Skill = the first platform where an AI agent designs, validates, and deploys workflows autonomously.** The human stays in control (nothing deploys without confirmation), but the design work is AI-driven.

## Who Benefits

- **RPA Engineers** — faster workflow creation, less clicking
- **Developers** — build workflows in their terminal, integrate with CI/CD
- **AI Agents** — can now generate and deploy qubi workflows programmatically
- **qBotica** — competitive advantage over UiPath, Automation Anywhere, Power Automate
